# Photos Unlimited

[English](README.md) · [Português (Brasil)](README.pt-BR.md) · [Español](README.es.md) ·
[简体中文](README.zh-Hans.md) · **日本語**

*この翻訳は言語モデルを使って作成されたもので、基準となる英語版 README より更新が遅れる場合があります。*

Google フォト ライブラリ向けの、小さな独立系 Android アップローダーです。フォルダを選んで
元の写真や動画をバックアップし、ライブラリの閲覧や編集には引き続き公式の Google フォト
アプリを使えます。

**Android 13 以降 · MIT ライセンス**

[ウェブサイト](https://venzellucas.github.io/photos-unlimited/) ·
[APK をダウンロード](https://github.com/venzellucas/photos-unlimited/releases/latest/download/Photos-Unlimited.apk) ·
[リリースノート](https://github.com/venzellucas/photos-unlimited/releases/latest)

**APK を検証してください。** すべてのリリースは、SHA-256 フィンガープリントが
`cbd14272c6aaa0568df8cc8be4ec10be9c6a2ebc0354eb202b5a05d8cda74bce`
である証明書で署名されています。Android は、この鍵で署名されていないアップデートを拒否します。
各リリースには、APK のチェックサムも `SHA256SUMS.txt` に記載されています。セキュリティ上の
問題を報告するには、[SECURITY.md](SECURITY.md) をご覧ください。

## できること

- 元のファイルをバックアップする写真と動画のフォルダを選択できます。
- 手動でバックアップを実行するほか、従量制でないネットワークや充電中といった条件を
  指定して、Android のスケジュールに自動処理を任せることもできます。
- 現在のファイルの進行状況、アップロード履歴、既存のものと一致したファイル、再試行が
  必要なファイルを確認できます。
- ネイティブの Material 画面、ライト/ダークテーマ、壁紙の色、アダプティブ アイコン、
  利用可能な場合はキャッシュした Google プロフィール写真を使用します。
- Google フォトのメタデータをスキャンして、報告されているストレージ使用量を確認できます。
  メディアの種類や、容量が加算されるもの・不明なものでフィルタできます。この機能は
  試験的なプレビューです。
- アプリは English、Português (Brasil)、Español、简体中文、日本語で利用できます。
  スマートフォンの言語に従いますが、設定 → **言語** で別の言語を選べます。

root 権限、カスタム ROM、microG、API キー、Photos Unlimited のサーバーは不要です。

## インストールと接続

1. リリースから署名済みの APK をダウンロードします。Android から、ブラウザからの
   インストールを許可するよう求められる場合があります。設定を引き継ぐには、既存のバージョンの
   上にインストールしてください。
2. アプリ内の Google のセットアップ ページからアカウントを接続します。Google が埋め込み型の
   ログインを拒否した場合は、接続画面に記載されているブラウザのセットアップ トークンによる
   代替手段を使ってください。このトークンはアプリ内にのみ入力し、Issue やメッセージには
   決して投稿しないでください。
3. すべての写真と動画へのアクセスと、メディアの位置情報へのアクセスを許可します。後者は、
   埋め込まれた位置情報を含む完全な元のファイルのバイト列を読み取るために必要です。
4. フォルダを選択します。選択したフォルダ内の既存のファイルは、最初のバックアップに
   含まれます。
5. 公式の Google フォト アプリで自動バックアップをオフにしてから、**今すぐバックアップ**を
   タップします。これにより、Photos Unlimited の自動バックアップも有効になります。

アプリは開いている間、1 日に 1 回 GitHub を確認し、新しいバージョンが公開されるとカードを
表示します。これをオフにするには、設定 → **アップデートを確認** を使います。アカウント
ボタンにイニシャルが表示されている場合は、それを開いて**プロフィール写真を更新**を選びます。
プロフィールの取得には別の読み取り専用トークンを使い、実行は 1 日に最大 1 回です。取得に
失敗しても、アップロード用の認証情報は無効になりません。高度な設定にある電話のアカウント
選択は診断用であり、バックアップ用のサインインの代わりにはなりません。

## MVP の範囲

このアプリは、xob0t の GPMC と gotohp から流用した、Google の非公開のモバイル プロトコルを
使用します。Pixel のアップロード プロファイルを使って、元の画質での扱いを要求します。
**アップロードが受理されたことは、容量の対象外になる証明ではありません。** ストレージの
計上は Google が管理しており、その方法を変更したり拒否したりする可能性があります。
このアプリに頼る前に、新しいサンプルのアップロード、ダウンロード可能な元のファイル、
実際の容量の使用状況を確認してください。ライブラリに既にある一致する項目はスキップされ、
その計上はそのまま維持されます。

ストレージのスキャンの対象は Google フォトであり、Google ドライブや Gmail は対象外です。
不明な計上はゼロではありません。合計は、スキャンしたレコードについて報告された課金
バイト数を合計したもので、アカウント全体の使用量とは異なる場合があります。共有アイテム、
別バージョン、漏れ、同時に行われた変更が、対象範囲に影響することがあります。実際の
計上は完全には検証されていません。

## ストレージの空き容量を増やす

すでに Google のストレージを使用している項目は、このアプリでアップロードしたコピーに
置き換えられます。**ストレージ**で項目をタップするか、複数を選択してください(**対象をすべて
選択**はページをまたいで機能します)。Google はメディアをコンテンツ ハッシュで識別し、同じ
キーで削除するため、同一の置き換え用ファイルが存在できるようにするには、元のファイルが
先になくなっている必要があります。そのため、各項目は次のように処理されます。

1. Google の記録と照合されます(同じバイト列を持つ他の項目があってはなりません)。
2. 端末にあればそこからコピーを取得し、なければ Google からダウンロードします。ただし、
   その SHA-1 が、元のアップロードに対して Google が記録したハッシュと等しい場合にのみ
   受け入れられます。これによりバイト単位で同一のファイルであることが証明されるため、
   埋め込まれたメタデータ(EXIF の日付、GPS、カメラ、動画の位置情報)はそのまま保持されます。
3. ゴミ箱に移動されて完全に削除され、その後コピーが再びアップロードされます。
4. 置き換えたものについて Google が課金バイト数 0 と報告した場合にのみ確定されます。
   キャプション、お気に入り、アーカイブの状態は復元されます。

安全性に関する特性:

- すべての手順は実行前に記録(ジャーナル)されるため、クラッシュしても安全に再開できます。
  削除前にコピーが変化した場合は、元のファイルがゴミ箱から復元されます。課金される置き換えや、
  確認が必要な項目があると、実行全体が停止します。
- コピーは、アプリの非公開ストレージではなく `Pictures/Photos Unlimited/Pending upload/`
  に保存されるため、アプリをアンインストールしたりデータを消去したりしても失われません。
  ファイル名には SHA-1 とアカウントの短いハッシュが含まれます。新しくインストールした
  アプリは、残っている各ファイルをそのハッシュで検証して処理を完了します(別のアカウントには
  決して行いません)。このアプリが書き込んだファイルだけが自動的に完了されます。以前の
  インストールが残したファイルは、まず一覧表示されて承認を求められ、他のアプリが書き込んだ
  ファイルは無視されます。一時保存したコピーは、Google 上に同じチェックサムを持つ、有効で
  ゴミ箱に入っていない項目が表示されて初めて削除されます。端末上にしかないものがある間は
  アンインストールしないよう通知で警告し、アカウントの変更は完了するまで待機し、
  Android のアンインストール ダイアログにはデータを保持するオプションが表示されます。
- 削除の直前に、項目が再度検索され、引き続き対象であること、ゴミ箱への移動が Google の記録に
  表示されていることが必要です。また、削除から置き換えの確定までの間にある項目は、常に 1 つ
  だけです。
- **先に Google フォトのバックアップをオフにしてください。** バックアップがオンの間、
  Google フォトは、クラウドから削除されたものの端末上のコピーを、アカウントのすべての
  デバイスで削除します
  ([Google ヘルプ](https://support.google.com/photos/answer/6128858))。空き容量を増やす機能は
  この操作を求め、安全策として、削除された端末上のコピーをバイト単位で同一の状態で元に
  戻します。
- **保存容量の節約画質の項目**は、元のファイルが端末にまだ残っている場合(Google が記録した
  ハッシュで証明されます)にのみ元のファイルに置き換えられ、Google の縮小されたコピーが
  代わりに使われることはありません。これにより、2021 年より前の無料の縮小版アップロードも
  アップグレードされます。
- **モーション フォト**(Pixel、Samsung)は単一のファイルなので、動きが保持されます。Google が
  同一の埋め込み動画を再抽出します。**iPhone のライブフォト**は動画を別のファイルに保持して
  いるため、動きが失われないよう、置き換えは拒否されます。

置き換えで失われるもの: アルバム、共有アルバムのコピー、コメント、顔グループ、そして Google
フォト内で行った日付/位置情報などの編集。Google フォトのバックアップがオンになっている他の
デバイスは、引き続きそのコピーを削除する可能性があります。テスト アカウントで実際に検証
しました(写真、動画、保存容量の節約画質の項目、モーション フォト、アプリのデータを消去した
後に復旧した、実行の途中で停止した動画)。ただし、大規模な実際のライブラリではまだ検証
されていません。

### Google フォトのバックアップに関するリマインダー

1 台のスマートフォンで 2 つのバックアップ アプリが競合するうえ、Google フォトによるコピーは
ストレージを消費します。Android ではアプリが Google フォトの設定を読み取れないため、自動
バックアップがオンの間、Google フォトのバックアップをオフにしたことを確認するまで、アプリは
起動のたびに確認を求め、その**バックアップ**ページに直接リンクします。再び確認を求めるのは、
他のアプリが先にアップロードした新しい写真を後から検出した場合だけです。

バックグラウンドのスケジュールは Android が管理しています。ネットワーク、バッテリー、充電、
アイドルに関するルールにより、処理が遅れることがあります。アプリを強制停止すると、再び開く
まで自動処理は停止します。ファイル転送が中断された場合は、そのファイルを最初からやり直します。
非常に大きな動画は、安定した接続で手動実行する必要があるかもしれません。RAW、HDR、編集は
形式ごとの検証が必要です。別々の写真/動画ファイル(iPhone のライブフォト)は、ペアとして
組み立てられません。

## ビルド

JDK 21 と Android SDK のプラットフォーム/ビルドツール 37 を使用します。`ANDROID_HOME` か、
追跡対象外の `local.properties` ファイルを設定してください。リポジトリには Gradle ラッパーが
含まれています。

```sh
./gradlew --no-daemon --max-workers=2 :app:assembleDebug :app:testDebugUnitTest :app:lintDebug
```

デバッグ APK は `app/build/outputs/apk/debug/` にあります。デバッグ ビルドでは、インストール
済みの署名済みリリースをアップデートできません。インストルメンテーション テストは、使い捨て
のテスト用エミュレータでのみ実行してください。

```sh
ANDROID_SERIAL=YOUR_TEST_EMULATOR ./gradlew :app:connectedDebugAndroidTest
```

リリース ビルドでは、`PHOTOS_KEYSTORE` と `PHOTOS_SIGN_PASSWORD` を使って外部のキーストアを
指定し、`ANDROID_HOME` を設定してから、`RELEASE_TAG=vX.Y.Z tools/build-release.sh` を実行します。
ここで `X.Y.Z` は `app/build.gradle` の `versionName` です。APK とその `SHA256SUMS.txt` は
`dist/X.Y.Z/` に書き出されます。これらの値やキーストアは決してコミットしないでください。
リリースの署名鍵は、アップデートをまたいで保管してください。

ライブラリのマスクは、`blackboxprotobuf` と、以下に記載の固定された GPMC のチェックアウトを
使って、`tools/generate-library-templates.py` で再生成できます。

## 検証

各リリースは、JVM と Android のインストルメンテーション テスト スイート、エラーなしの lint、
前のリリースからの署名済みのその場でのアップグレードに合格しています。バージョン 1.0.0 では、
独立したセキュリティ レビュー(指摘事項はリリース前に修正済み)と、前述のとおり実際の
空き容量を増やす機能の実行も行いました。テストは、プロトコルの処理、確定したアップロード、
中断、永続化されたキュー、アカウントの分離、メタデータのページネーション、外観、プロフィール
キャッシュの分離をカバーしています。テストの認証情報とネットワーク応答は合成されたもの
です。ライト/ダークと大きな文字サイズの画面を確認しました。これらの検証は、実際の容量の
対象外になることや、ライブラリの完全な計上を証明するものではありません。
